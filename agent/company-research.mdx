---
title: Company research
description: Find each company's news stories from a list of domains.
---

Send `companies` to `POST /runs`. The agent finds each company's news stories
in the window you set, optionally only the ones about a topic.

```json
{
  "companies": {
    "items": [
      { "domain": "stripe.com" },
      { "domain": "adyen.com", "name": "Adyen" }
    ],
    "save_as_list": true,
    "list_name": "Payments"
  },
  "query": "funding and acquisitions",
  "lookback_days": 90
}
```

## Parameters

<ParamField body="companies" type="object" required>
  The companies: `list_id` of a [company list](/agent/company-lists), or
  `items`, each with a `domain` (a URL works too) and an optional `name`.
  `save_as_list: true` also saves typed items as a list, named `list_name`.
</ParamField>

<ParamField body="query" type="string">
  Keep only stories about this, for example "funding and acquisitions". Blank:
  every story about the companies.
</ParamField>

<ParamField body="lookback_days" type="integer" default="30">
  How many days back from today: 1 to 365. `0` becomes 30.
</ParamField>

<ParamField body="include_market_activity" type="boolean" default="true">
  Keep market activity stories: stock moves and analyst ratings.
</ParamField>

<ParamField body="read_web" type="boolean" default="true">
  Also read each company's own newsroom and the web, not only the news.
</ParamField>

<ParamField body="recheck_borderline" type="boolean" default="true">
  A stronger model rechecks borderline web pages for companies with little
  coverage.
</ParamField>

<ParamField body="keep_updated" type="object">
  Make a company monitor of the run once it succeeds. See
  [Monitors](/agent/monitors).
</ParamField>

Company runs always use the `standard` mode. A company run with another `mode`,
or with `max_rows`, is refused with `invalid_options` (`422`).

## Large lists

Free and pay-as-you-go runs take up to 50 companies. On
[Enterprise plans](/get-started/enterprise-plans), a run of more than 50
companies is split into runs of up to 50, grouped in a
[batch](/agent/runs#batches). The response then has a `batch_id` and the
`run_ids` of every part.

## Story columns

A companies run returns one story per row. A story is a group of articles about
the same event. The `rows` of the result and the CSV and Excel exports have
these columns:

| Column | Meaning |
|---|---|
| `domain` | The company's domain. |
| `company` | The company's name. |
| `rank` | Position of the story within its company, `1` first. Stories covered by more independent outlets rank higher, `importance` breaks ties, and market activity ranks last. |
| `date` | Date of the story's earliest article (`YYYY-MM-DD`). |
| `story_type` | What happened: `funding`, `acquisition`, `leadership`, `workforce`, `financial_results`, `product`, `partnership`, `legal_regulatory`, `incident`, `expansion`, `market_activity` or `other`. `unscreened` means the agent could not check the story's articles; it has `importance` `0` and ranks last. |
| `importance` | How much the story matters to someone tracking the company, from `1` to `5`. `5`: major, such as an acquisition, a CEO change, a large funding round, financial results, a major lawsuit or fine, large layoffs or a major launch. `3`: notable. `1`: trivial, such as a small price move or a passing promotion. The agent rates each article; a story takes its highest rating. |
| `headline` | Headline of the lead article, in English when a translation exists. When that headline is cut off or too short, the agent's one-line description of the event instead. |
| `summary` | One-line abstractive summary of the story, in English: an AI model writes what happened in its own words instead of copying the text, with the company as the subject, in about 15 words at most. The agent writes such a line for each article, and the story keeps the one that best represents its articles. Empty for `unscreened` stories. |
| `outlets` | Number of different publishers that covered the story. News aggregators are not counted. |
| `articles` | Number of articles in the story, copies of the same article included. |
| `source` | Domain of the lead article: the article that best shows the story. |
| `url` | Link to the lead article. |
| `origin` | Where the story was found: `news` (news articles), `web` (web search only) or `own` (only the company's own website). |
| `related_company` | Empty for now. |

## Coverage per company

Besides the stories, a companies run returns one row per company in
`companies`, with what the agent found:

| Status | Meaning |
|---|---|
| `found` | Stories were found. |
| `no_news` | The company was searched and has no stories in the window. |
| `incomplete` | The search for the company did not finish; the stories found so far are kept. |
| `identity_unknown` | The agent could not tell which company the domain is. The company was not searched and has no stories. |
| `out_of_time` | The company reached its time limit. It has no stories. |
| `model_unavailable` | The AI model did not respond. The company has no stories. |
| `internal_error`, `failed` | The search for the company failed. It has no stories. |
| `pending` | Not reached yet; the run is still going. |
| `not_searched` | The run ended before reaching the company. |

Each company has up to 20 minutes. A company that reaches that limit shows
`out_of_time`, and the run goes on with the other companies.

The run still ends `succeeded` when some companies were not searched in full:
see [Best practices](/agent/best-practices#requests).

Download it with `GET /runs/{run_id}/companies.csv` or `companies.xlsx`.

If the run used a company list, fix a company with `identity_unknown` in the
list: see [Fix a company](/agent/company-lists#fix-a-company).
