---
title: Event research
description: Turn a description of events into a verified table, one event per row.
---

Send a `query` without `companies` to `POST /runs`. The agent finds the events
that match, decides which columns the question needs, and fills one row per
event.

```json
{
  "query": "Bank M&A deals announced in the US since Sep 15",
  "mode": "standard",
  "max_rows": 100
}
```

## Writing the request

The `query` is the whole brief. Put in it:

- **what happened**: deals, recalls, layoffs, lawsuits, product launches;
- **who or where**: an industry, a country, a type of company;
- **when**: "since Sep 15", "in Q3 2026", "last week". Event runs read their
  time window from the query;
- **what to capture**, if it matters: "with the buyer, the target and the deal
  value".

<CodeGroup>
```text Good
Data breaches disclosed by US hospitals since July 1, with the number of patients affected
```

```text Too vague
hospital breaches
```
</CodeGroup>

## Parameters

<ParamField body="query" type="string" required>
  What to find, with its time window. The news search covers the last 365
  days, so a window such as "the last 12 months" works.
</ParamField>

<ParamField body="mode" type="string" default="fast">
  `fast`, `standard` or `max`. See [modes](/agent/overview#modes).
</ParamField>

<ParamField body="max_rows" type="integer" default="50">
  The most rows to return: 50 or 100. More is refused with `too_many_rows`.
  A run is charged per 50 rows delivered past the first 50. A started block
  counts in full: 51 rows cost the same as 100.
</ParamField>

<ParamField body="keep_updated" type="object">
  Make a monitor of the run once it succeeds. See [Monitors](/agent/monitors).
</ParamField>

<ParamField body="webhook_ids" type="string[]">
  Webhooks to send the results to when the run succeeds, up to 20. See
  [Webhooks](/agent/runs#webhooks).
</ParamField>

## Choosing a mode

- **`fast`** for a first look, or when 1 to 3 minutes matters more than recall.
- **`standard`** when every row must be checked against its sources and you
  want a cited briefing with the table.
- **`max`** for the hardest lists, where missing an event costs more than the
  extra time and price.

## What you get

`GET /runs/{run_id}` returns, once the run has finished:

- `columns` and `rows`: the table;
- `report`: the cited briefing that `standard` and `max` runs write;
- `evidence`: for `standard` and `max` runs, the sources behind each row. See
  [Results and exports](/agent/results-and-exports#the-table).

`window_from` and `window_to` are empty for events runs. The agent reads the
window from your query, so check the rows' dates.

## Get more rows

When a run found every row it asked for, there may be more. Continue it
instead of starting a new run: `POST /runs/{run_id}/continue` with
`max_rows`, the run's new total of rows.

```bash
curl -X POST "https://api.newscatcherapi.com/agent/runs/RUN_ID/continue" \
  -H "x-api-key: $NEWSCATCHER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"max_rows": 100}'
```

The answer is `202` with `run_id`, `continuation_id`, `status`, `rows` (the
run's rows now) and `max_rows`. Follow the continuation with
`GET /runs/{continuation_id}/progress`, and cancel it with
`POST /runs/{continuation_id}/cancel`. When it succeeds, its new rows are added
to the run: `GET /runs/{run_id}` and the exports have every row, and the run's
[webhooks](/agent/runs#webhooks) get the whole table again.

- The continuation first uses what the run already found but did not deliver,
  then searches the news further. It keeps the run's mode and columns.
- Rows the run already has (same link, same key columns or same event) are left
  out, so a continuation can add fewer rows than you asked for.
- You pay only for the 50-row blocks the new rows start beyond the blocks the
  run already paid for: 50 rows, then 50 more, cost the same as 100 rows at
  once. A continuation that adds nothing is free. See
  [Credits and pricing](/get-started/credits-and-pricing#agent).
- One continuation adds up to your plan's `max_rows` (more gets
  `too_many_rows`). A run reaches 1,000 rows at most.

`continuable` in `GET /runs/{run_id}` says whether the run can be continued
now. Only its owner can continue it, and only a succeeded events run that
found every row it asked for: a run that found 10 of 50 has nothing more to
give, so start a new run instead (`standard` and `max` search more widely).
After a continuation, the same holds for what it found. A run can be continued
until it is archived, 30 days after it ended. Runs made before continuing
became available cannot be continued.

| Code | Status | Meaning |
|---|---|---|
| `run_not_continuable` | `409` | Not a succeeded events run, it found fewer rows than it asked for, it is archived, or it is itself a continuation (the message names the run to continue). |
| `run_busy` | `409` | The run is already being continued. Wait for that continuation to end. |
| `max_rows_too_low` | `422` | `max_rows` is not more than the rows the run has. |
| `max_rows_too_high` | `422` | `max_rows` is over 1,000, or adds more than one continuation can. |
