## The table

`GET /runs/{run_id}` returns the run with its result once it has finished:

<ResponseField name="columns" type="string[]">
  The column order. An events run has the columns its question needed; a
  companies run has one story per row, company first. See
  [Story columns](/agent/company-research#story-columns).
</ResponseField>
<ResponseField name="rows" type="object[]">
  The table, one event or story per row, keyed by column.
</ResponseField>
<ResponseField name="companies" type="object[]">
  Companies runs: one row per company asked for, with its
  [coverage status](/agent/company-research#coverage-per-company).
</ResponseField>
<ResponseField name="outcome" type="string">
  A finished companies run or batch: `partial` when at least one company
  failed, else `complete`. The run's `status` stays `succeeded` either way.
  `null` while it runs and for events runs.
</ResponseField>
<ResponseField name="company_counts" type="object">
  Companies runs: how many companies ended with each coverage status, for
  example `{"found": 30, "no_news": 12, "out_of_time": 1}`.
</ResponseField>
<ResponseField name="companies_failed" type="integer">
  Companies runs: how many companies failed (`out_of_time`,
  `internal_error`, `model_unavailable` or `failed`). They are not charged.
</ResponseField>
<ResponseField name="window_from / window_to" type="string">
  Companies runs: the time window the run covered. Empty for events runs.
</ResponseField>
<ResponseField name="report" type="string">
  The cited briefing that `standard` and `max` runs write with the table.
</ResponseField>
<ResponseField name="evidence" type="object[]">
  `standard` and `max` runs: the sources behind each row, in the order of
  `rows`. Each item has `outlets`, the number of outlets that reported the
  event, and `sources`, each with `url`, `source`, `published` and `quote`.
</ResponseField>
<ResponseField name="continuable" type="boolean">
  Events runs: whether you can [get more rows](/agent/event-research#get-more-rows)
  with `POST /runs/{run_id}/continue` now. `null` for companies runs.
</ResponseField>
<ResponseField name="continuation" type="object">
  The continuation in progress, with `continuation_id`, `max_rows`,
  `rows_before` and `created_at`. `null` when none is running.
</ResponseField>
<ResponseField name="continuations" type="object[]">
  The continuations that ended, each with `continuation_id`, `status`
  (`succeeded`, `failed` or `cancelled`), `max_rows` (the run's new total),
  `rows_before`, `rows_added`, `found` (rows found before repeats of the
  run's rows were left out), `finished_at` and `error` (the error code, when
  it failed).
</ResponseField>
<ResponseField name="continue_of" type="string">
  On a continuation: the id of the run it adds rows to.
</ResponseField>

## Downloads

| File | Run | Batch | Monitor run |
|---|---|---|---|
| The table as CSV | `/runs/{run_id}/export.csv` | `/batches/{batch_id}/export.csv` | `/monitors/runs/{run_id}/export.csv` |
| The table as Excel | `/runs/{run_id}/export.xlsx` | `/batches/{batch_id}/export.xlsx` | `/monitors/runs/{run_id}/export.xlsx` |
| Company coverage as CSV | `/runs/{run_id}/companies.csv` | `/batches/{batch_id}/companies.csv` | |
| Company coverage as Excel | `/runs/{run_id}/companies.xlsx` | `/batches/{batch_id}/companies.xlsx` | |

A monitor run's file starts with the `change` column (`new` or `update`), then
the stories' or rows' columns.

```bash
curl -o result.xlsx "https://api.newscatcherapi.com/agent/runs/RUN_ID/export.xlsx" \
  -H "x-api-key: $NEWSCATCHER_API_KEY"
```
