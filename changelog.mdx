<Update label="November 27, 2026" description="Agent 1.21.0">
  ## Page through a monitor's story feed

  - **Paging**: `GET /monitors/{monitor_id}/stories` takes `offset` next to
    `limit` and returns `total` and `offset`, so you can read the whole feed
    page by page. The feed now holds up to 5,000 stories instead of 500.
    Without `offset`, you get the same first page as before. See
    [Page through the story feed](/agent/monitors#page-through-the-story-feed).
  - **Truncated feed**: the answer returns `truncated: true` when the feed has
    more than 5,000 stories and the older ones are left out.
  - **Fixed**: a monitor made from a run now shows that run's stories in its
    feed before its first scheduled run.
</Update>

<Update label="November 26, 2026" description="Agent 1.19.4">
  ## Stories from the source run in a monitor's feed

  - **Fixed**: a company monitor made from a companies run now shows that
    run's stories in `GET /monitors/{monitor_id}/stories` before its first
    scheduled run, including to people it is shared with. Before, the feed
    stayed empty until the monitor ran. See
    [Monitors](/agent/monitors#get-what-a-monitor-delivered).
</Update>

<Update label="November 25, 2026" description="MCP server 0.4.0">
  ## More rows for a research run in the MCP server

  - **More rows**: when an events run found every row it asked for, the
    [MCP server](/integrations/mcp) says so, and the assistant can add rows to
    it: up to 100 at a time, up to 1,000 per run. You pay only for the extra
    50-row blocks; a dry run shows the cost for free. See
    [Get more rows](/agent/event-research#get-more-rows).
  - **Run size**: an events run asks for 50 or 100 rows. Larger numbers are
    lowered to 100; add rows to the run for more.
  - **Free monitor**: monitor lists mark your organization's free monitor.
  - **Fixed**: when the API is slow to answer, a tool now returns an error
    with a Correlation-ID instead of no answer.
</Update>

<Update label="November 25, 2026" description="Agent 1.19.3">
  ## Continuation fields

  - **Fixed**: each entry in `continuations` on `GET /runs/{run_id}` now
    returns only `continuation_id`, `status`, `max_rows`, `rows_before`,
    `rows_added`, `found`, `finished_at` and `error`. See [Results and exports](/agent/results-and-exports).
</Update>

<Update label="November 25, 2026" description="Agent 1.19.2">
  ## Continue a run with more rows, and the free monitor flag

  - **Continue a run**: add rows to a succeeded events run with
    `POST /runs/{run_id}/continue` and `max_rows`, the run's new total, up to
    1,000. The continuation uses what the run already found first, leaves out
    rows the run has, and adds the new rows to the run. You pay only for the
    extra 50-row blocks, so 50 rows then 50 more cost the same as 100 at
    once. Only a run that found every row it asked for can be continued:
    `GET /runs/{run_id}` returns `continuable`. See
    [Get more rows](/agent/event-research#get-more-rows).
  - **Free monitor flag**: every monitor has `free`, which is `true` on your
    organization's free monitor. See
    [Free monitor](/get-started/credits-and-pricing#free-monitor).
</Update>

<Update label="November 24, 2026" description="Agent 1.18.0">
  ## Webhooks, search and paging, and company run outcome

  - **Webhooks**: send a run's or a monitor's new results to your endpoint.
    Attach webhooks you made in the Platform with `webhook_ids` on
    `POST /runs` and `POST /monitors`, and send results again with
    `POST /runs/{run_id}/webhooks/deliver` or
    `POST /monitors/{monitor_id}/webhooks/deliver`. See
    [Webhooks](/agent/runs#webhooks).
  - **Search and paging**: `GET /monitors` and `GET /companies/lists` take
    `q`, `limit` and `cursor`, and return `next_cursor` and `total`. Without
    `limit`, both answer as before. See
    [List your monitors](/agent/monitors#list-your-monitors) and
    [List your lists](/agent/company-lists#list-your-lists).
  - **Company run outcome**: `GET /runs/{run_id}` and `GET /batches/{batch_id}`
    return `outcome` (`complete` or `partial`), `company_counts` and
    `companies_failed`, so you can tell when companies failed in a run that
    succeeded. See
    [Coverage per company](/agent/company-research#coverage-per-company).
  - **Large company runs**: your companies now take turns, so a company's time
    limit starts when its search starts. Large runs take longer, and fewer
    companies end `out_of_time`.
  - **Sharing and projects in the Platform**: runs, monitors and company lists
    shared with you open for you, `shared=true` lists them, and
    `POST /runs/{run_id}/copy` copies a public run with its results into your
    account for free. See
    [Shared runs, monitors and lists](/agent/runs#shared-runs-monitors-and-lists).
  - **Fixed**: company monitors no longer search the same 30 days again on
    every run for busy companies, which used to end `incomplete`.
  - **Fixed**: a company that failed midway now shows `out_of_time` or
    `model_unavailable` instead of `internal_error`. Company runs and monitor
    runs no longer replace a finished company's result with `internal_error`
    or fail as a whole because of it.
</Update>

<Update label="November 23, 2026" description="MCP server 0.3.0">
  ## Webhooks and search in the MCP server

  - **Webhooks**: ask the assistant to send a run's or a monitor's results to
    your webhooks. Give it the webhook ids from the Platform's **Webhooks**
    page. The new `resend_results` tool sends results again, for free. See
    [MCP server](/integrations/mcp#tools).
  - **Search and paging**: find a monitor by name or topic, or a company list
    by name or by a company in it ("which list has Stripe?").
  - **Company runs**: results start with how many companies were done, had no
    news or failed, and say that failed companies are not charged.
</Update>

<Update label="November 20, 2026" description="News API 1.3.12">
  ## Whole-day dates, robots.txt filter and better publishers

  - **Breaking**: on `/articles`, a `to_date` without a time now means the end
    of that day (23:59:59), so `from_date=2026-10-03&to_date=2026-10-03`
    returns that whole day. If you sent a date-only `to_date` to leave that
    day out, send the day before. See
    [Filters](/news/filters#only-for-articles).
  - **`robots_compliant`**: filter `/articles` by whether articles comply with
    the publisher's robots.txt rules. When you use it, each article carries
    `robots_compliant`. See [Filters](/news/filters#only-for-articles).
  - **NOT in `/search`**: `-word` and `!word` now leave a word out, as `NOT`
    does. Before, `-word` had no effect and `!word` searched for the word. See
    [Writing queries](/news/writing-queries#excluding-terms-with-not).
  - **Original publishers in `/search`**: when an article was found on several
    sites, the result now shows the original publisher's copy instead of an
    aggregator's. See [Response fields](/news/response-fields#article).
  - **Fixed**: `/search` answers with `503` less often. When part of the
    search is briefly unavailable, it now returns results from the rest.
</Update>

<Update label="November 16, 2026" description="Agent 1.8.3">
  ## Fixes for long windows and failed searches

  - **Fixed**: `standard` and `max` event runs that ask for "the last 12
    months" find news again. Before, they ended with no rows. See
    [Event research](/agent/event-research#parameters).
  - **Failed searches are free**: a run whose news searches all failed now
    fails with `search_failed` and is not charged, instead of succeeding with
    0 rows. A run whose searches worked but found nothing is still charged. See
    [Credits and pricing](/get-started/credits-and-pricing).
</Update>

<Update label="November 16, 2026" description="Agent 1.8.2">
  ## Large company runs and monitors finish

  - **Company monitors**: a monitor run now refreshes every company it follows,
    however many there are. Before, a run stopped after 60 minutes and skipped
    the companies it had not reached. See [Monitors](/agent/monitors#schedule).
  - **Company monitors**: if a run is still going when the next scheduled time
    comes, the monitor skips that time instead of starting a second run.
  - **Fixed**: a company that runs out of time no longer fails the whole
    company run. It shows `out_of_time`, and the run goes on with the other
    companies. See
    [Coverage per company](/agent/company-research#coverage-per-company).
  - **Fixed**: companies with a very large amount of news, such as Apple or
    Microsoft, no longer run out of time before any news is found.
  - **Fixed**: large company runs and monitor runs no longer fail when one part
    of the work stops on an internal error. That part starts again.
</Update>

<Update label="November 12, 2026" description="MCP server 0.2.0">
  ## Sign in to the MCP server

  - **Sign-in**: connect the [MCP server](/integrations/mcp) with your
    NewsCatcher account instead of an API key. Add
    `https://mcp.newscatcherapi.com/mcp` to Claude.ai, Claude Desktop or
    Claude Code, click **Connect** and sign in. The server uses the Default
    API Key of your default workspace. API keys keep working as before. See
    [Authentication](/integrations/mcp#authentication).
  - **Cursor Marketplace**: install the NewsCatcher plugin, with the server and
    53 skills, from **Customize > Plugins** in Cursor.
</Update>

<Update label="November 9, 2026" description="Agent 1.7.0">
  ## Clearer progress messages

  - **Progress**: when a search query is too long to show in full in a
    progress message, it now ends with `…`, so you can tell it was shortened.
    The search itself always uses the whole query. See
    [Follow a run live](/agent/runs#follow-a-run-live).
  - **Removed**: the `conversation_id` field of `POST /monitors` and of monitor
    responses. It had no effect, and the API now ignores it. See
    [Monitors](/agent/monitors).
  - **Fixed**: a query that contains quoted phrases now shows exactly as you
    wrote it in progress messages.
</Update>

<Update label="November 4, 2026" description="Agent 1.5.0">
  ## Company monitor price

  - **Company monitors**: following a company now costs about $3 per company per
    month (was $1.50). Event monitors, event research and company research
    prices do not change. See
    [Credits and pricing](/get-started/credits-and-pricing#agent).
</Update>

<Update label="November 4, 2026" description="News API 1.1.0">
  ## Articles

  - **`/articles`**: list every article that matches a boolean query over the
    last 12 months, newest first, and page through up to the first 1,000
    matches. Each call costs 5 NCC. See
    [Articles](/news/articles).
  - **Plan limits**: `GET /subscription` now returns an `articles` field with
    the page size, depth, history, requests per second and price of
    `/articles`. See [Rate limits](/get-started/rate-limits#check-your-plan).
  - **New error status**: `408` when an `/articles` search runs out of time. It
    is not charged. See [Errors](/get-started/errors).
  - **Fixed**: when a part of the service does not answer in time, you now get
    `503` with a `Retry-After` header instead of `500`. The request is not
    charged and does not count toward your daily request limit. See
    [Errors](/get-started/errors).
</Update>

<Update label="October 30, 2026" description="Launch">
  ## New News API and Agent

  - **News API**: `/search` ranks the last 30 days of news in every language,
    groups results into stories and summarizes each article, at three
    [effort levels](/news/effort-levels).
  - **Stories**: `/stories/{story_id}` lists every article of one story.
  - **Agent**: research events or companies in the background and get a
    table, once or on a schedule with [monitors](/agent/monitors).
  - The News API, the Web Search API and the Local News API docs move under
    **Enterprise** in the version menu.
</Update>
