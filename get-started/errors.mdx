title: Errors
description: Error responses, what they mean and when to retry.
---

Use the HTTP status to decide what to do:

| Status | Meaning | Retry the same request? |
|---|---|---|
| `400` | The request was refused; its `code` says why (agent). | No, fix it first |
| `401` | The API key is missing or invalid. | No |
| `402` | Your credit balance does not cover the request. | After topping up |
| `403` | Your plan does not include what you asked for, or the key may not use this API. | No |
| `404` | Unknown story, run, list or monitor. | No |
| `409` | The request conflicts with the current state of the run, list or monitor (agent). | After the state changes |
| `413` | The uploaded file is too large (agent). | No |
| `422` | A parameter is missing, invalid or unknown, or the body is not valid JSON. | No, fix it first |
| `429` | A rate limit of your plan. | Yes, after `Retry-After` seconds |
| `500` | Something failed on our side. | Yes, and send us the `Correlation-ID` |
| `503` | A part of the service is temporarily unavailable. | Yes, after a short wait |

## Error body

<Tabs>
  <Tab title="News API">
    ```json
    {
      "message": "What went wrong and what to do about it.",
      "status_code": 402,
      "status": "Payment Required"
    }
    ```

    `message` is meant for people: do not parse it. Use `status_code`.
  </Tab>
  <Tab title="Agent">
    ```json
    {
      "code": "too_many_rows",
      "message": "What went wrong and what to do about it."
    }
    ```

    `code` is stable: use it in your code. `message` is meant for people.
  </Tab>
</Tabs>

## Tracing a request

Every News API response carries a `Correlation-ID` header and an
`X-Process-Time` header. Quote the `Correlation-ID` when you contact support.
